# PhysioFlow API

Modular monolith. NestJS 12 (ESM) · PostgreSQL 16 · Drizzle ORM · Passport JWT.

Implements the foundation slice of [`plans/01-platform-tenancy.md`](../../plans/01-platform-tenancy.md)
and [`plans/02-identity-access.md`](../../plans/02-identity-access.md): tenant isolation,
the grant matrix, cross-reference guards, and staff authentication.

```bash
npm install
```

```bash
npm run db:up && npm run db:migrate && npm run db:seed
```


Seeded login: `owner@physioflow.test` / `physioflow-dev-password`.

| Script | Does |
|---|---|
| `db:up` / `db:down` | Local Postgres + Redis via Docker |
| `db:generate` | Regenerate `0000_foundation.sql` from the Drizzle schema |

| `test` | Integration tests against the real database |
| `test:e2e` | HTTP tests through the full Nest stack |
| `lint` / `typecheck` / `build` | oxlint · tsc · nest build |

## Two database roles, and why it matters

| Role | Used by | Powers |
|---|---|---|
| `physioflow_owner` | migrations, seeds, test fixtures | superuser — **bypasses RLS entirely** |
| `physioflow_app` | the API, at runtime | non-superuser, `NOBYPASSRLS`, `SELECT/INSERT/UPDATE` only |

The application never connects as the owner. `DATABASE_APP_URL` is the runtime
connection; `DATABASE_URL` exists for migrations.

This split is also why the test suite is trustworthy. Every isolation assertion runs on
`physioflow_app`. A suite that seeds *and* asserts as the owner proves nothing, because
the policies are never consulted — that is the failure mode called out in PRD §15.4, and
`tenant-isolation.spec.ts` includes a test that the same query **does** return rows as the
owner, so the suite would notice if it silently started running with the wrong role.

## Tenant context

Every request runs inside one transaction that begins by setting two GUCs:

```sql
select set_config('app.clinic_id', $1, true),
       set_config('app.user_id',   $2, true)
```

The third argument — `true` — makes the setting transaction-local. Session-local would
outlive the request and leak the tenant to whoever borrows that pooled connection next.
`tenant-isolation.spec.ts` asserts the setting is gone in the following transaction.

`DrizzleService.runInTenantTransaction()` is the only way in, and
`TenantTransactionInterceptor` applies it to every route. Guards run before interceptors,
so the principal from the JWT is already resolved when the transaction opens.

There is one deliberate escape hatch, `DrizzleService.autonomous()`, used by exactly one
caller — see "Reuse detection" below.

## Authentication

- Argon2id via `@node-rs/argon2` (chosen over `argon2` for prebuilt binaries; the package
  exports `Algorithm` as an ambient const enum that `isolatedModules` cannot read, so the
  variant is inlined as a constant and `argon2id.spec.ts` asserts the resulting hash
  actually carries the `$argon2id$` prefix).
- 15-minute access tokens; refresh tokens rotate within a family and are stored as
  SHA-256 hashes only.
- Login and refresh are the only paths that run without a tenant context, so their reads
  go through `SECURITY DEFINER` functions rather than through relaxed policies.
- A missing account and a wrong password both verify against a hash and both return 401,
  so neither timing nor status code enumerates users.

**Reuse detection.** Presenting an already-redeemed refresh token revokes the whole
family. The revocation runs on its own connection *outside* the request transaction —
otherwise the 401 that follows rolls it back and a stolen family stays live. This was a
real bug caught in review; `auth.e2e-spec.ts` locks it down by asserting that the
legitimately-rotated token is also dead afterwards.

## Isolation, in three layers

1. **RLS** — enabled *and forced* on all 8 tables, policies wrapped as
   `(select app_current_clinic_id())` so the planner evaluates them once per query rather
   than once per row (NFR-PRF-07).
2. **`SECURITY DEFINER` cross-reference guards** — RLS confirms a row's own `clinic_id`;
   it says nothing about whether the *referenced* row belongs to another clinic. Without
   `DEFINER` the lookup returns NULL, the comparison is NULL rather than true, and the
   guard admits exactly the row it exists to reject.
3. **Privilege level** — no `DELETE` granted on any table. Every table therefore needs a
   soft-void path; `memberships.revoked_at` is the pattern.

## Migrations

`0000_foundation.sql` is generated by drizzle-kit. `0001_security.sql` is hand-written and
holds every policy, grant, guard and index; it is registered in `meta/_journal.json` by
hand. **Never edit an applied migration** — corrections are new migrations.

## What is not built yet

This is the foundation only. No patients, episodes, appointments, packages or money —
those are plans 03 through 15. Notably absent and needed before anything is built on top:
`audit_logs` plus actor columns, which [`plans/15-audit-compliance.md`](../../plans/15-audit-compliance.md)
argues belong in Release 1 while there is no history to backfill.
